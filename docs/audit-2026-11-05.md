## The short list — distinct issues that matter

**Wrong declared figures or lost data (critical)**

1. **A payment present in two linked statements is declared twice.** — fixed (owner's list item 13) The row fingerprint that decision 23 promised would tell overlapping exports apart is stored and indexed but never read; every linked sheet is matched on its own. An export of 1.–15. beside one of 1.–31., or a bank CSV beside the accountant's .xlsx copy of it, declares the shared payments twice, with no warning (items 1 and 33).
2. **A payment in a foreign currency is declared as that number of euros.** — fixed (owner's list item 13) The grid shows the currency, but nothing in the defaults, the checks or the build looks at it; the XML writes every amount as EUR (item 11).
3. **The minimum share follows the newest valid contract even when it carries no minimum.** — fixed (owner's list item 13) With a Tööleping and a newer VÕS or board row, the month's minimum is measured by the wrong contract's days, and a month without pay gets no zero line (item 23).
4. **A paused contract standing for the month counts its pause as employed days.** — fixed (owner's list item 13) A person on leave with a small payment is topped up to the full kuumäär, against decision 84 (item 24).
5. **Every month is computed with the 2026 rates.** — fixed (owner's list item 13) Only one rate set exists and nothing picks by the period's year; from January 2027 the kuumäär and the exemptions are silently wrong (items 25 and 38). Correct for every month the channel accepts today.
6. **A Save on a stale person card after the register lookups writes the old residency and pension back and marks them Manual** — fixed (owner's list item 13), so later lookups never correct them (items 37 and 12).
7. **A second store restore by an older copy deletes the store the first restore set aside** — fixed (owner's list item 13), with whatever work existed only there (items 56 and 35).

**A flow that breaks or misleads (major)**

8. A person's register binding is rewritten at every load, so a month whose register writes the person under another key (with or without a code) creates a duplicate person (items 13 and 32). — fixed (owner's list item 14)
9. A file imported after "Otsi maksed" is linked but the old run stays in force; its rows are missing from the grid, the Vahearuanne and the lines with no warning (item 14). — fixed (owner's list item 14)
10. A refused payment's line kept on the server is not subtracted from the month's exemption and minimum, so the month can claim the exemption twice (item 26). — fixed (owner's list item 14)
11. A pension-age person cannot store an exemption of exactly 700: the card saves it as "the allowance in force", which is 776 (item 27). — fixed (owner's list item 14)
12. A version settled "on the server" by mistake can never be taken back; the key is stuck (item 34). — fixed (owner's list item 14)
13. The persons grid stays usable while a run is busy, so a click can save a person on the UI thread while the worker uses the same connection (item 39). — fixed (owner's list item 14)
14. Opening another store with unsaved card edits saves them into the new store, which fails, and the edits are lost (item 40). — fixed (owner's list item 14)
15. The export does not notice that the review changed after the last "Koosta read" (item 41). — fixed (owner's list item 14)
16. "Märgi kinnitatuks" passes lines that MTA refused black, as if they were on the server (item 49). — fixed (owner's list item 14)
17. The feedback's texts, the resend advice and the server's own tax figures are never shown; a whole-file refusal's reason appears nowhere (item 50). — fixed (owner's list item 14)
18. A lookup run for any month, locked ones included, overwrites the facts every other month is built with (item 63). — fixed (owner's list item 14)

**Said as minor by the refuters but worth a decision:** a file already in the store is never read anew, so parser fixes do not reach it (item 2); another employer's rows in a shared TÖR export become this company's persons (item 3); a foreign-A1 person gets a zero line MTA flags (item 27 of the tax area); a re-uploaded file's OK report cannot lift lines a file-level refusal rejected (item 49 of the export area); a withdrawn export stays on disk under a normal name (item 51); the store-restore offer appears at any start of an older copy, before the update check (item 57); a cancel between the residency and pension queries leaves a stale "not a member" (item 64).

**Suggested order (after the criticals, fixed the same day).** 11 and 16 are small and self-contained; 8, 10 and 18 touch the declaring rules and want the three-lens review; 9, 12, 13, 14, 15 and 17 are window and flow work; the minors want a word each from the owner.

### 22. [minor] A register person with a two-word name is never searched for successfully, and nothing says so — FIXED (item 34 of the owner's list, 2026-11-09: the search extended, option 2)

When a register person's first or last name contains a space, NameSearch can never match the bank's ordinary spaced spelling.
